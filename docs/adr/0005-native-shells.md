# ADR 0005 — Native store shells via Capacitor 7

- Status: accepted · Date: 2026-10-16

## Decision
Wrap the PWA build (`dist/`) with **Capacitor 7** for iOS and Android. Native projects live in
`ios/` and `android/` and are committed (minus build outputs, per Capacitor's own .gitignores).
Native haptics come from `@capacitor/haptics`, bridged in `src/platform/native.ts` (web: no-op).

## Why Capacitor 7, not 8
Capacitor 8 requires Node ≥ 22; this machine and CI use Node 20. 7.x is current-supported and
upgrading later is a `npx cap migrate`.

## Notes / gotchas
- Xcode on this machine supports iOS ≥ 15; the template targets 14. Raised to 15.0 in the app
  project and forced for Pods in `ios/App/Podfile` post_install.
- `appId` is a placeholder (`com.example.atoll`) — **must be replaced** with the owner's id.
- Verified: iOS Simulator (iPhone 17) build + launch + screenshot. That run found a real bug: the
  safe-area inset probe read 0 at startup in WKWebView, so the score sat under the Dynamic Island.
  Fixed with a persistent probe + ResizeObserver.
- Android project generated but **not built**: no Android SDK on this machine.

## Workflow
`npm run build && npx cap sync` then open `ios/App/App.xcworkspace` in Xcode or `android/` in
Android Studio. `make ios-sim` builds and launches the simulator app.

## Update 2026-10-16 (session 2)
- Android command-line SDK installed (owner approved). Debug and **signed release** builds verified:
  `make android-emu` (Android 15 emulator, real `adb input swipe` drags) and `make android-release`
  (AAB 5.9 MB). Signing reads `android/keystore.properties` (gitignored); verified with a throwaway
  key in /tmp, then deleted. The owner must create the real upload key.
- Icons and splashes for both platforms are generated by `scripts/native-assets.ts`.

## Update 2026-10-16 (milestone review)
- **iOS minimum raised to 16.4** (`IPHONEOS_DEPLOYMENT_TARGET` in the app project and forced for
  Pods in the Podfile). iOS 15 was never really playable: canvas `roundRect` (Safari 16) threw on
  the first frame and `color-mix()` (16.2) blanked the gradient headline. 16.4 also brings the
  Web Share / user-activation behaviour the share card relies on. Cheap insurance stays anyway:
  plain-colour fallbacks before each `color-mix()` in style.css, and the render loop schedules the
  next frame first and logs (once) instead of dying on a throwing draw.
- **Service worker policy** (public/sw.js): web/PWA only — never registered inside the Capacitor
  shells (the app is already local; a cache there only strands players on an old build), and the
  shells unregister any worker an older build left behind (seen on the Android emulator: the old
  cache-first worker served a stale index pointing at deleted chunks → blank screen). On the web it
  is registered as `sw.js?v=<build id>` (`__BUILD_ID__`, version + build time), so every deploy is a
  new worker with its own cache; activate deletes older caches. Navigations/index are network-first
  with cache fallback, hashed `assets/*` cache-first, other files stale-while-revalidate; a JS/CSS
  miss is an error, never index.html. Install precaches the entry chunks so the shell boots offline.
  Lazy-chunk failures aren't cached (retry chip), and `vite:preloadError` reloads once (guarded).
- **Share plugins**: `@capacitor/share` + `@capacitor/filesystem` 7.x. In the shells the share card
  is written to the cache dir and handed to the system sheet (Android WebView has no
  `navigator.share`, and `<a download>` does nothing in either WebView). The web keeps Web Share
  with files → download. Outcomes are honest: closing the sheet is `cancelled`, no path is `failed`.
  `make ios-sim` and `make android-emu` build and launch with the three plugins.
